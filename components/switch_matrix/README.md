# switch_matrix

A hub type ([hub](../hub/gm_hub.h), [core/README.md "Virtual pins and hubs"](../../core/README.md#virtual-pins-and-hubs)): `switch_matrix.c` (the driver: its rows and columns at init), `__init__.py` (the YAML: validation and generated C). Its config (`.sm`, `include/gm_device.h`) and state (`gm_hub.h` `u.sm`) stay in the core, with the scan's path in `core/src/vpin.c`: `vpin_scan_matrices` (one load per row where the columns are adjacent bits of one input register), the hardware scan's `vpin_scan_plan` / `vpin_scan_feed`, and the button spans (`vpin_span_take`, `vpin_read_span`). Its host test is `core/test/test_matrix.c` (`test_matrix`, `test_matrix_hw`), with the key matrix's.

`switch_matrix` is up to 32 switches scanned from the scan interrupt: `rows` (MCU pins or decoder outputs), `columns` (MCU input pins), `settle` (wait after driving a row, default 1us), `rows_per_scan` (rows read per scan, in turn; default all). Pin n = row n / columns, column n % columns, 1 = closed. Buttons and encoders. It is scanned right after the key matrix, so the two can share column pins (`allow_other_uses: true` on each use); see [Matrices behind decoders](../../core/README.md#virtual-pins-and-hubs).
