# decoder

A hub type ([hub](../hub/gm_hub.h), [core/README.md "Virtual pins and hubs"](../../core/README.md#virtual-pins-and-hubs)): `decoder.c` (the driver: its address and enable lines), `__init__.py` (the YAML: validation and generated C). Its config (`.dec`, `include/gm_device.h`) stays in the core, with the scan's path in `core/src/vpin.c`: `vpin_write` selects an output itself, with one precomputed set/reset store where its lines are all on one port (`vpin_select_word` gives the key scan that store). Its host test is `core/test/test_matrix.c` (rows behind decoders, as on the Code 61).

`decoder` is one or more 74HC138-style chips sharing address lines: `address` (1–4 pins, A0 first), optional `groups` (1–4 mappings of enable pin to level, e.g. `{ PB6: 1, PB7: 0 }`). Output n = address n % 2^address-pins in group n / 2^address-pins. Its outputs are one-of-N row selects, so only matrix rows (`key_matrix`, `switch_matrix`), given as `rows: { decoder: rows, first: 16, count: 4 }` or `{ decoder: rows, number: n }` pins. An output is selected when its row is driven ("on") and stays selected until the next row's select replaces it ("off" does nothing). See [Matrices behind decoders](../../core/README.md#virtual-pins-and-hubs).
